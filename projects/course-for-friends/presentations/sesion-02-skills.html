Punto 1

Qué es una skill y para qué sirve

Punto 1

¿Qué problema resuelve?

Claude Code olvida todo entre conversaciones — cada vez que lo abres, empieza desde cero (salvo lo permanente en tu CLAUDE.md). Una skill resuelve algo distinto: un archivo de texto con instrucciones permanentes para una tarea o proceso específico — no todo tu contexto general, sino "así se hace esto".

Analogía: sin skill = empleado nuevo que olvida todo cada día. Con skill = empleado que tiene el manual de esa tarea puntual en la mesa y lo consulta cada vez que la hace.

Punto 1

CLAUDE.md vs. Skill

CLAUDE.mdSkill
¿Cuándo se lee?Siempre, en cada mensajeSolo cuando la tarea la necesita
¿Qué es?El "quién eres"El "así se hace X"
Las skills son opcionales — no las necesitas para empezar, pero son el siguiente paso natural en cuanto te repites haciendo el mismo proceso.

Punto 1

Los 3 usos

  • Consistencia — le comunicas tu framework, tono, o estilo de código preferido para ese tipo de tarea
  • Automatizar workflows — guarda instrucciones de tareas repetitivas
  • Conocimiento del proyecto — documenta reglas propias de un proceso para que Claude las recuerde siempre

Punto 2

Anatomía de un SKILL.md

Punto 2

Las dos partes

  • Front matter (YAML) — entre líneas ---. Lo único que Claude Code lee en la primera pasada (~100 tokens). name y description son obligatorios
  • Instrucciones paso a paso — el cuerpo en markdown, lo que Claude ejecuta una vez decide que es la skill correcta
  • Campos opcionales — disable-model-invocation, allowed-tools, argument-hint, model, hooks, agent

Punto 2

Ejemplo mínimo

---
name: seguimiento-cliente
description: Redacta un mensaje de seguimiento para un
  cliente que no ha respondido en X días. Úsala cuando
  pidan "mándale seguimiento a [cliente]".
---

1. Pregunta hace cuántos días fue el último contacto.
2. Redacta un mensaje corto (máx. 3 frases), tono
   profesional pero cercano.
3. Nunca prometas descuentos ni fechas de entrega sin
   que el usuario las confirme.

Punto 2

Regla + estructura de archivos

  • Regla oficial — mantener el SKILL.md por debajo de 500 líneas; lo que no quepa se mueve a archivos aparte
  • Self-contained — todo bajo la misma carpeta de la skill (SKILL.md + scripts/ + references/ juntos)
  • Separado — scripts/referencias viven en otra parte del proyecto y el SKILL.md los referencia por ruta — útil si varias skills comparten archivos
  • Los scripts que puede ejecutar una skill normalmente son Python o JS

Punto 3

Local vs Global

Punto 3

¿Dónde viven?

tu-proyecto/
└── .claude/
    └── skills/
        └── nombre-de-la-skill/
            └── SKILL.md

La carpeta .claude se crea sola al instalar la primera skill. Claude Code la revisa cada vez que abres el proyecto — no hace falta activar nada a mano.

Punto 3

¿Local o global?

Local (un proyecto)Global (todos los proyectos)
Carpetatu-proyecto/.claude/skills/~/.claude/skills/
Cuándo usarlaReglas de ese proyecto específico: ese cliente, esas tecnologíasHábitos tuyos de siempre: idioma, estilo, preferencias generales

Punto 3

¿Cómo se instala?

  • Terminal — claude skill install nombre.skill (local) o --global
  • VS Code — ícono ✦ → escribir /plugins → panel de gestión
  • Lenguaje natural (recomendada hoy) — "Instala esta skill de forma global / solo en este proyecto"

Punto 4

Cómo decide Claude cuándo usarla

Punto 4

Dos formas de disparar una skill

  • Explícita — slash command con el nombre (ej. /seguimiento-cliente) → dispara directo, sin ambigüedad
  • Lenguaje natural — Claude lee el CLAUDE.md, analiza la petición y compara contra el description de cada skill instalada
El description que le pongas a tu skill es lo único que decide si se dispara sola. Uno vago = nunca se activa por lenguaje natural.

Punto 5

Framework de 6 pasos

Punto 5

Para construir tu propia skill

  1. Nombre y trigger — cómo se llama y qué frase la debería disparar
  2. Objetivo — en una frase: ¿qué logra y cuál es el output final?
  3. Proceso paso a paso — si lo hicieras a mano, ¿qué harías, en qué orden?
  4. Archivos de referencia — ¿qué contexto extra hace falta?
  5. Reglas — ¿qué puede salir mal? ¿qué guardrails hacen falta?
  6. Ciclo de auto-mejora — cómo se va a ir afinando con el uso

Punto 5

Atajo: skill-creator

Existe una skill oficial llamada skill-creator que automatiza este mismo framework: va haciendo las 6 preguntas y construye el SKILL.md por ti.

Útil para ir más rápido, pero vale la pena que la primera vez lo pienses tú punto por punto, para entender qué está pasando por debajo.

Punto 6

El ciclo de feedback

Punto 6

Ninguna skill sale perfecta a la primera

  1. Invocar
  2. Observar cómo trabaja el agente
  3. Dar feedback
  4. El agente ajusta el SKILL.md
  5. Repetir
Después de 10-30 ejecuciones con ajustes, el resultado se vuelve consistente.

Punto 6

¿Cuándo crear una skill?

En el día a día después del curso: cuando se descubran repitiendo el mismo proceso, o corrigiendo a Claude siempre de la misma forma (ej. "no uses guiones largos").

No hace falta que sea compleja — puede ser un .md de 50 líneas.

Punto 6

Testing y debugging: síntoma → fix

SíntomaFix
Hace los pasos mal o en el orden equivocadoEditar las instrucciones del SKILL.md
Falta tono, estilo o contextoAñadir un archivo de referencia y apuntarlo desde el SKILL.md
Comete el mismo error una y otra vezAñadir una regla explícita
No se dispara cuando deberíaRevisar el YAML — el description no es lo bastante específico
Se dispara demasiado seguidoConsiderar disable-model-invocation
Funciona bien pero podría mejorarNo hay atajo — iterar: ejecutar, observar, afinar

Punto 7

Hands-on de cierre

Punto 7

Cada quien construye su primera skill real

Sobre el mismo proyecto de la Sesión 1

  1. Identificar la tarea — algo que hacen más de una vez en su negocio
